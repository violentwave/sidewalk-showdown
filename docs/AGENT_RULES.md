# Agent Rules — Sidewalk Showdown

Every coding agent working in this repo follows these rules. Read
`docs/PM_BRIEF.md` for the project state; this file is the contract.

## Setup and branching

1. Work from a **worktree** branched off `origin/main` (`git worktree add ...`),
   never inside another agent's checkout, and never commit on `main`.
2. **Investigate first.** Read the owning script and `.tres` data before
   changing behavior; docs can be stale — code and tests are the truth.
   `docs/PM_BRIEF.md` §9 flags which docs are stale.
3. Do not edit files another agent is editing in the main checkout; create new
   files or coordinate through PRs.

## Verification discipline

4. Run **all headless suites before and after** your change (they are fast
   except `combat_test`/`cpu_test`; a display is only needed for manual
   capture tools):
   `godot --headless --path game --script res://tests/combat_test.gd` (and
   round_flow, character_select, locomotion_speed, stage_select, stage_floor,
   cpu, combo, combo_fuzz, the_clip, serialization, b6_landing_whiff).
   `air_probe.gd` is metrics-only. Every CI step has a `timeout-minutes`,
   but still run hanging-prone tooling under a shell timeout locally.
5. Paste **real output** in the PR (checks + failures per suite), not claims.
   If your change alters a suite's check count, update the count **everywhere**
   it is written: `README.md`, `docs/PHASE_STATUS.md`, `docs/KNOWN_ISSUES.md`,
   and `docs/PM_BRIEF.md`.
6. Visual changes need a rendered review: capture with
   `DISPLAY=:0 godot --path game --resolution 1280x720 --script ...`, check
   both facings, and attach before/after evidence.

## Simulation rules (non-negotiable)

7. Fixed 60 Hz. All gameplay timings are simulation frames; presentation
   counters ride the same clock so pause/hitstop freeze everything.
8. **Determinism**: no gameplay RNG (only the CPU's seeded LCG), no
   wall-clock, no `delta`, no node-order dependence, deterministic equal-x
   tie-breaks.
9. **Every new simulation state joins `serialize()`/`load()`** (match,
   fighter, CPU) and is frame-counted. See `docs/SAVESTATE_PLAN.md`.
10. **Meter builds only on landed hits.** Whiffs and blocks award nothing
    (blocked pays `meter_gain_block * METER_GAIN_ON_BLOCK_SCALE`, 0.0). Never
    reintroduce whiff/receive gain.
11. Knockdown rejects all throws and non-METH strikes (K1/R1); chip floors at
    1 HP; damage scaling is 100/100/85/70/55 with a 55% floor; juggle cap is 3
    airborne hits. These are pinned owner decisions — don't "fix" them.
12. Presentation never changes gameplay: clips/cadence/scale are visual only.
    Keep gameplay-data PRs separate from presentation-only PRs.

## Data and art pipeline

13. **Fighters are data.** Balance lives in `game/resources/**/*.tres`,
    regenerated by `godot --headless --path game --script
    res://tools/gen_fighter_data.gd`; combat code never hard-codes per-fighter
    values. Adding a fighter/stage is a roster edit, not a code edit.
14. **`art/source/` is read-only.** Never clean or overwrite owner batches;
    runtime art lives in `game/art/`; stage prep scripts
    (`art/tools/prepare_*.py`) are owner-run.
15. **No Python in agent sessions** — shell and Godot headless tooling only.
16. Image generation: stay **under 8 images per request**, follow the
    `docs/PIXELLAB_ASSET_ORG.md` identity locks, save generated originals to
    review folders, and never move art into `game/art/` without owner review.

## Input-map gotcha

17. The input map is generated (`game/tools/setup_input.gd`), never
    hand-edited. After regenerating, **re-add the `[physics]
    physics_ticks_per_second = 60` section** that `ProjectSettings.save()`
    silently drops, or the simulation clock changes.

## Landing

18. Small, single-purpose commits. Branch from `origin/main`, open a PR with
    the template filled (real suite output), wait for **green CI** on all
    suites, then **squash-merge** and delete the branch. Direct pushes to
    `main` are auto-reverted by the `main-guard` workflow.
19. Every PR that changes features, tests, commands, or rules must update
    `docs/PM_BRIEF.md` (and the other user-facing docs as applicable).
